# Code audit: opbounty-stats (React 18 + Vite SPA), branch claude/audit

Scope: src/App.jsx, src/daten.js, src/main.jsx, src/index.css, helpers. Read only, static analysis plus small node probes (no project file changed).
Method notes: an AST scope check over all src/*.js(x) found zero undeclared identifiers (only Uint32Array, a builtin), so the KaizokuListe class of bug (deleted but still referenced) is absent right now. The log parsers (partieLesen, eindampfen, schritteBauen) were fed garbage, binary and empty text and did not throw. Findings marked "logic-verified" were traced through code, not reproduced in a browser.

## P0 (page breaks or blank)

### P0-1 No React error boundary anywhere
src/main.jsx:9-13 renders `<StrictMode><App/></StrictMode>`; grep for ErrorBoundary, componentDidCatch, getDerivedStateFromError returns nothing in src.
Impact: any render time exception in any tab (this is exactly what blanked the player page on 06.11.2026) unmounts the entire tree, header and tab bar included, so the user cannot even switch tabs.
Fix: add one class based ErrorBoundary around the tab content in the `buehne` (App.jsx ~4208) keyed by `reiter`, showing a message plus a "Back to Decklists" link, and a second one around `<App/>` in main.jsx as last resort.

## P1 (a whole area is dead or a common path misbehaves)

### P1-1 One failed fetch kills the whole app, error page has no navigation and no source picker
App.jsx:4044-4055 (`if (fehlerText && !satz)` returns a bare error page), fed by App.jsx:3834-3842 (verzeichnis fetch) and 3892-3896 (satz fetch). The default `wahl.satz` is hard coded (App.jsx ~3636).
Impact: if the default set file or the directory file is missing or returns 5xx once, Leaderboard, Guide, Analyze, Changelog and Player (none of which need `satz`) are unreachable, and the user cannot pick another source because the Quelle chip lives in the header that this page omits. The message also blames local setup ("Run python3 aktualisieren.py") which is wrong for a visitor.
Fix: render the normal shell (header, tabs) with the error inline in `buehne`, and only show the loading/error state inside the leader bound tabs; reword the message for visitors.

### P1-2 Deep links /player?id=... and /replay?p=... are overwritten by the generic address effect
App.jsx:3813 and 3819 set `?id=` / `?p=`, then the effect at App.jsx:3987-3990 runs on the same `reiter` change and calls `adresseSetzen(reiter, gewaehlt, false, null, null, matrixSort)`. In `adresseSetzen` (App.jsx ~3427-3448) the spieler/replay branches build the query only from `spielerId` / `replayPfad`, which are `null` in that call, so the target becomes bare `/player` or `/replay` and is pushed as a new history entry (logic-verified).
Impact: the URL in the address bar loses the player or replay after the first render, so copied links, reloads and Back/Forward land on "This player is not in the current top 100" or "Pick a game to watch its replay"; history also gets a duplicate entry per navigation.
Fix: pass `spielerId` and `replayPfad` in the call at 3989 (or skip the call when `reiter` is "spieler" or "replay"), and use `replaceState` for the secondary effect.

### P1-3 Unlock path can leave a permanently blank page or a stuck button
App.jsx:3724-3741 runs `await anmelden(gemerkt)` inside an async IIFE with no try/catch; `anmelden` (daten.js:~136-158) calls `crypto.subtle.importKey/deriveKey` and `ausBase64(info.salz)`, which throw when `crypto.subtle` is undefined (page opened over plain http or an embedded webview) or when schluessel.json is malformed. `entsperrt` then stays `null` and App.jsx:4041 `if (entsperrt === null) return null;` renders nothing. The same call in Schloss.absenden (App.jsx:3486) has no try/catch either: after `setLaeuft(true)` a throw leaves the button on "Checking" forever.
Impact: blank screen or dead login form with no message for any visitor whose browser cannot do WebCrypto; it is also an unhandled promise rejection.
Fix: wrap both calls in try/catch, set `entsperrt` to false (or a dedicated "unsupported" state with a message) and reset `laeuft` in a finally.

## P2

### P2-1 Failed `holen` results are cached forever; the retry in kartenHolen is a no-op
daten.js:184-203: `zwischenspeicher.set(datei, versprechen)` is never cleared on rejection (metacoachHolen does clear, line ~278). `kartenHolen` (daten.js:307-314) therefore awaits the same rejected promise on its "retry", and `kartenLaden` is called once (App.jsx ~3763).
Impact: one 503 on karten.json.gz leaves every leader as a card number until reload, contradicting the comment that says exactly this was fixed; a single failure of bestenliste/spieler/analyse files also sticks for the session.
Fix: in `holen`, `versprechen.catch(() => zwischenspeicher.delete(datei))` like metacoachHolen does.

### P2-2 schluessel.json network error is treated as "no encryption" and cached
daten.js:121-127: `catch { schluesselInfo = false }`.
Impact: a transient offline blip on the first request makes the app try plain `.json.gz` URLs that do not exist in production, ending in the misleading P1-1 error page, and the wrong answer is memoised until reload.
Fix: only cache `false` on a definitive 404; on network error rethrow and show a retry state in Schloss.

### P2-3 Empty data set leaves every tab on "Loading" forever
App.jsx:4152-4153: `if (!leader) inhalt = <p className="laedt">Loading</p>`, and `leader` (App.jsx ~3935) is `undefined` when `satz.leader` is empty (empty range, empty Kaizoku file; `verschmelzen` filters non-leader ids). `laedt` is already false.
Impact: Rankings, Matrix, Mulligan, Guide, Leaderboard and Changelog all show an endless spinner text instead of an empty state.
Fix: distinguish `!satz` (loading) from `satz && !satz.leader.length` (render "No games in this range" and still render the tabs that do not need a leader, e.g. changelog, beste, eigenes, spieler, replay, book).

### P2-4 Leaderboard crashes if the file lacks `spieler`
App.jsx:1173 `daten.spieler.map(...)` (Bestenliste), while the player tab at App.jsx ~4175 guards with `beste.spieler ? ... : null`. `setBeste(d)` accepts any parsed JSON.
Impact: a truncated or differently shaped bestenliste.json.gz blanks the page (no boundary, see P0-1).
Fix: `(daten.spieler || []).map` and show the "No ladder snapshot yet" state when empty.

### P2-5 Mulligan per matchup assumes the file shape and uses `!== null` for optional numbers
App.jsx:2032 `Object.entries(daten.gegner)` and `(y.partien.first + ...)` in the sort, App.jsx:2038 `w !== null ? w.toFixed(1)`, plus `k.wr_behalten - k.wr_weg`.
Impact: a file without `gegner`, or a row where `wr_behalten` is missing (undefined, not null) throws TypeError inside render and blanks the tab.
Fix: `Object.entries(daten.gegner || {})`, `w != null` (loose), and default `partien` to `{}`.

### P2-6 KaizokuListe / Spieler assume `decks` and `gegner` exist (same component class as the 06.11 incident)
App.jsx:3260 `kzSpieler.decks.map(...)` and App.jsx:3326 `liste.gegner.length` (Spieler passes `gegner: d.gegner`, which is optional in the data; the Deckzeile path guards it, this one does not).
Impact: a top100 player whose kaizoku_spieler entry lacks `decks`, or a deck lacking `gegner` after clicking the record button, blanks the player page.
Fix: `(kzSpieler.decks || [])` and `(liste.gegner || [])`.

### P2-7 Replay: whole event log is rendered on every step even while hidden
App.jsx:1929-1951: `r-log` gets class `hidden` when `logOffen` is false, but `schritte.map` still builds one button per event (hundreds) on every `setI`, including autoplay ticks at 175 ms (tempo 4x).
Impact: avoidable DOM churn and jank on phones during playback.
Fix: render the list only when `logOffen` is true.

### P2-8 Long date ranges hold up to 30 day files parsed in memory permanently
daten.js:493-495 `Promise.all(dateien.map(holen))`; the file header states one day is about 4.8 MB raw JSON; preset buttons go to 30d (App.jsx ~560) and every parsed file stays in `zwischenspeicher` forever.
Impact: roughly 150 MB of JSON text parsed on the main thread at once, and retained as the user switches ranges; likely tab kill on low memory phones.
Fix: cap the preset or load sequentially; stop caching the parsed day objects once merged (keep only the merged set), or move parsing to a worker.

### P2-9 No live regions or document title updates
grep shows `role="status"` only in the card preview (App.jsx:258-259); error `<p className="meldung fehler">` (App.jsx ~4207, 4053) and "Loading" paragraphs are silent, and `document.title` is never set, so every tab and the history list say "Letacios Fiesta".
Impact: screen reader users get no feedback on load/error, and tab switches (client side) announce nothing.
Fix: `role="alert"` on `.meldung.fehler`, `aria-live="polite"` on the loading paragraphs, set `document.title` and move focus to the `h1` on tab change.

### P2-10 Touch targets below 44 px on primary controls
index.css:707-720 `.knopf` min-height 36; index.css:756-765 `.feld` min-height 36; index.css:691-693 `.schalter button` about 28 px; index.css:483-489 `.dreh` 30x30 and 26x24 on phones (index.css:1925-1929); `.voreinstellung .knopf` 30 px (index.css:2841); tab bar links are 48 px and `.rknopf` 44 px (OK).
Impact: segmented switches (Games/Win rate/Lists, Going first/second) and sort headers are hard to hit on a phone; the row itself is clickable so the chevron is partly redundant.
Fix: raise to `min-height: 44px` inside the `max-width: 760px` block for `.knopf`, `.feld`, `.schalter button`, `.sitzwahl button`, `.leiste-knopf`.

## P3 (at most five)

### P3-1 Unknown `?leader=` on /matrix leaves a half active focus state
App.jsx:fokusAusAdresse (~3415-3420) accepts any card number shaped string; `Matrix` falls back to the full matrix when no entry matches, but `matrixFokus` stays truthy, so the Sort switch (App.jsx:4272) and the "Show all N" button (App.jsx:4286) are hidden and the bogus id is kept in the URL.
Fix: validate against `satz.leader` once the set is loaded and reset to null.

### P3-2 Changelog nests h2 inside h2
App.jsx:2143 `<h2>` per date inside `Abschnitt`, whose own `<h2>` is "Changes" (App.jsx:397). Replay tab has no `h1` at all (Replay component, App.jsx ~1717). Fix: use h3 for the dates and add a visually hidden h1 to the replay view.

### P3-3 ARIA roles that have no parent
App.jsx:858 and the fokus header (App.jsx ~900-905) use `role="columnheader"` / `role="row"` on spans inside a plain div and ol, which is invalid without a table/grid parent; `aria-sort` is therefore ignored. Matrix cells use mouse only `onClick` on `<td>` (App.jsx ~1007-1025), but the "Show first and second" button offers the same function. Fix: drop the roles, keep the buttons.

### P3-4 Dialog focus handling is inconsistent
The ⌘K palette (App.jsx ~3566) and the mobile More sheet (App.jsx:4455) declare `aria-modal="true"` / `role="dialog"` but do not trap or restore focus like Kartenvorschau does (App.jsx:196-240), and the More sheet has no Escape handler dependency on focus. Fix: reuse the Kartenvorschau focus trap.

### P3-5 Saved password in localStorage and misleading "not in top 100"
App.jsx:3495 stores the plain password under `lf.pw`; an XSS or shared browser exposes the data key. Also `/player` with `beste === false` (file failed) shows "not in the current top 100" (App.jsx ~3180) instead of a load error. Fix: store only the derived key if the product requires remember-me (CryptoKey is non extractable here), and branch on `beste === false`.
